# Plan de desarrollo

1. Base actual: documentación, configuración, solución por capas, reglas con pruebas, simuladores, plantillas iniciales, vista previa, borrador simulado e historial mínimo.
2. Validación de negocio: revisar textos y casos con responsables; confirmar políticas pendientes, horarios, costo, siguiente evento y catálogos. Mejorar interfaz con ejemplos ficticios.
3. Outlook de sólo lectura y borradores: confirmar requisitos de laptop, perfil y PST; integrar Interop detrás de interfaces y probar con autorización. Sin envío ni movimiento.
4. Registros: conocer esquema, crear consulta de sólo lectura y resolver homónimos/estados. No actualizar automáticamente.
5. Clasificación y estadísticas: categorías/carpetas autorizadas, retención, reportes; movimientos sólo tras autorización explícita.
6. Automatización parcial: casos informativos de bajo riesgo con criterios medibles; borradores primero. Envío automático requiere autorización de una fase posterior. Documentación, rechazos, folios y excepciones humanos.
7. Evaluar IA sólo si aporta valor frente a reglas simples y se resuelve privacidad. No depende de Codex en ejecución.

Cada fase debe ser pequeña, compilable y probada. Prioridad: exactitud, seguridad, corrección humana, plantillas, Outlook, automatización y finalmente IA.
